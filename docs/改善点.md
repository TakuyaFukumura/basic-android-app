# リポジトリの改善点

この文書は、現在も対応が必要な改善項目だけを管理する。完了した項目はこの一覧から削除し、実装とテストの履歴はGitで確認する。

## 未対応項目

| 優先度 | 分野 | 改善項目 | 主な対象 |
| --- | --- | --- | --- |
| 高 | CI | Android SDKの整合性と継続的な品質ゲートを整備する | `.github/workflows/ci.yml` |
| 中 | データ層 | Roomのスキーマ管理、マイグレーション、テスト用DBを整備する | `AppDatabase.kt`, `data/` |
| 中 | アーキテクチャ | UI状態と画面・コンポーネントの責務をさらに分割する | `MainViewModel.kt`, `MainActivity.kt` |
| 中 | 依存関係 | 更新時の互換性確認と脆弱性スキャンの手順を自動化する | `gradle/`, `.github/` |
| 中 | リリース | 署名付きRelease成果物を手動承認付きWorkflowで生成する | `app/build.gradle.kts`, `.github/` |
| 低 | ドキュメント | 文書一覧と更新ルールをREADMEからさらに充実させる | `README.md`, `docs/` |
| 低 | 開発体験 | フォーマット、静的解析、レビュー用チェックリストを標準化する | `.github/`, Gradle設定 |

## 補足

- CRUD操作、空入力、100文字境界、DB失敗のユニットテストと、一覧アイテムのComposeテストを整備済み。
- ViewModelのエラーは型付き状態とAndroidログへ反映し、読み込み失敗には再試行導線を提供している。
- 初期データ投入は既存データを削除せず、空のデータベースにだけ行う。
- UI文言はリソースへ集約し、入力文字数表示、主要操作のアクセシビリティ情報、一覧アイテムのPreviewを整備済み。
- CIのLint・単体テスト・デバッグビルド、Roomスキーマ出力、ReleaseのR8設定、Dependabot、アーキテクチャ文書は整備済み。

## 推奨する実施順序

1. RoomのMigrationTestとテスト用DBを追加する
2. UIイベントとComposableの責務を分割する
3. CIの定期更新・脆弱性スキャン・Release署名Workflowを追加する
4. フォーマットと静的解析を導入し、READMEとレビュー手順を更新する
